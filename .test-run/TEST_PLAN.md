# Chrome-Markdown-Edit 全功能 Playwright/360Chromex 测试实施方案

> 版本：v1.0（基于 2026-08-03 巡检报告的功能清单与 POC 验证结果）
> 目标：在 `D:\Documents\AI_Work_Temp\Chrome-Markdown-Edit` 目录内，用 Playwright 驱动 `360chromex.exe` 对扩展的构建产物进行多场景、全边界、全工况回归测试，确认每个功能的有效性与健壮性，对确认的 BUG 进行源码修复与复测。

---

## 1. 目标与范围

### 1.1 测试目标
- 验证 v1.5.0 全部功能在真实 Chromium 内核浏览器中的可用性。
- 覆盖正常路径、边界输入、异常工况。
- 发现的 BUG 经**第二次独立测试确认**后记录，并最终修复。

### 1.2 范围边界
- **可自动化测试（360Chromex + `vite preview` 静态服务）**：核心编辑、预览、Markdown 语法高亮、样式工具栏、中文查/替、大纲/任务/专注/打字机、主题切换、Callout/Base64/Mermaid/代码块语言补全、符号自动配对、粘贴为 Markdown、compare 模块 UI、翻译设置面板 UI 等。
- **受环境限制、本方案无法自动化覆盖**：
  - 扩展安装/加载/图标点击（`action.onClicked`）
  - 右键菜单（`contextMenus`）
  - `file://*.md` 的内容脚本拦截与 background `tabs.onUpdated` 拦截
  - `chrome.storage.local` 自动保存/历史快照环/会话恢复
  - 真实翻译 API 调用
  - 本地文件系统读写（打开本地 `.md`、保存、文件夹侧边栏）
  - 桌面端 Tauri EXE（本机无 Rust 构建环境）
- **处理方式**：上述受限项在方案中明确标注，并在测试报告中列为「环境限制，建议用户手动验证或换用 Chromium 扩展自动化环境」。

## 2. 环境与约束

### 2.1 浏览器
- 锁定 `D:\Tools\360Chrome\360chromex.exe`（来源：用户授权 + 技能 `playwright-360chrome` 硬约束）。
- 使用 `launchPersistentContext`，userDataDir 位于项目内 `.test-run/profile/`（从日常 `User Data` 只读复制而来，不复写外部配置）。

### 2.2 被测服务
- 先执行 `npm run build` 生成 `dist/`。
- 用 `vite preview --port 5173 --strictPort` 提供 `dist/` 静态服务。
- 测试入口：
  - 编辑器：`http://localhost:5173/src/editor.html`
  - 对比合并：`http://localhost:5173/src/compare.html`

### 2.3 关键环境限制（已 POC 验证）
- 直接 `page.goto('chrome-extension://...')` 在 360Chromex 下会被浏览器清空 body（安全策略），不可行。
- `vite preview` 可正常渲染编辑器页面，但此时 `chrome.storage.local` 等扩展 API 不存在；依赖这些 API 的功能会在控制台报异常，测试框架需捕获并分类。

## 3. 测试架构

### 3.1 目录结构（全部在项目内）
```
.test-run/
  profile/                # 浏览器 userData 副本（运行时生成，测试后清理）
  assets/                 # 测试用图片、md 样本
  screenshots/            # 每轮测试截图
  logs/                   # 控制台错误日志
  TEST_PLAN.md            # 本方案
  test-utils.mjs          # 启动/关闭/浏览器/断言/BUG 记录公共模块
  runner.mjs              # 顺序执行全部测试并汇总
  test-*.mjs              # 各功能测试脚本
  BUGS.md                 # 确认的 BUG 清单（执行后生成/追加）
```

### 3.2 启动流程
1. `npm run build` 确保 `dist/` 与当前源码一致。
2. 后台启动 `vite preview --port 5173 --strictPort`。
3. 复制 `D:\Tools\360Chrome\User Data` → `.test-run/profile/`。
4. `launchPersistentContext(.test-run/profile/, executablePath=360chromex.exe, headless=false, args=[--no-sandbox, --disable-blink-features=AutomationControlled])`。
5. 打开 `http://localhost:5173/src/editor.html` 或 `compare.html`。

### 3.3 断言与证据策略
- **DOM 断言**：等待关键元素可见/存在（`#editorContainer`、`.toolbar`、`#previewContainer` 等）。
- **文本断言**：通过 CodeMirror 6 的 DOM 结构读取编辑器文本，或读取预览区 HTML。
- **截图证据**：每个测试用例关键步骤截图，保存到 `.test-run/screenshots/<test>-<step>.png`。
- **Console 监听**：分类记录 `error`、`warning`，作为 BUG 线索。
- **二次确认**：每个失败的用例，在新 browser context 中独立复跑一次，只有两次均失败才写入 `BUGS.md`。

### 3.4 公共能力（`test-utils.mjs`）
- `startPreview()` / `stopPreview()`
- `launchBrowser()` / `closeBrowser()`
- `openEditor(page)` / `openCompare(page)`
- `setEditorText(page, text)`：通过 CodeMirror 6 的 DOM 注入或 keyboard type。
- `getEditorText(page)`：读取 CodeMirror 内容。
- `getPreviewHTML(page)`：读取预览区 HTML。
- `clickToolbar(page, id)` / `isVisible(page, selector)`
- `screenshot(page, name)`
- `recordBug(name, detail, screenshotPaths, consoleErrors)`：写入 `BUGS.md`

## 5. BUG 发现与确认流程

1. **首次失败**：记录测试脚本、输入、截图、console errors 到临时文件 `.test-run/first-failures.md`。
2. **二次确认**：独立重启浏览器与 preview 服务，仅重跑该失败用例，使用相同输入。
3. **确认标准**：二次测试仍失败 → 写入 `.test-run/BUGS.md`；二次测试通过 → 标记为偶发/不稳定，不写入 BUGS，但记录到 `.test-run/flakes.md`。
4. **BUG 记录字段**：编号、功能、用例、现象、复现步骤、截图路径、console errors、首次/二次失败时间、根因假设、修复状态。

---

## 6. 修复与复测流程

1. 对 `BUGS.md` 中确认的 BUG，定位 `src/` 源码，最小作用域修复。
2. 修复后重新 `npm run build`。
3. 用同一测试脚本对修复项做**第三次回归测试**，通过则标记「已修复并复测」。
4. 若修复引入新问题，回退并按「统一优先级裁决器」重新处理。
